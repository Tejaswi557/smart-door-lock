Project Overview & Abstract

Face Recognition Based Smart Door Lock and Access Monitoring System

College Project Prototype

Abstract: Traditional security mechanisms such as mechanical keys, RFID badges, and numeric PIN pads are susceptible to physical theft, duplication, and unauthorized sharing. This project introduces a self-contained, browser-executed Face Recognition Based Smart Door Lock and Access Monitoring System that performs real-time contactless biometric identity verification entirely within client-side web technologies.

Operating strictly within the browser environment via the HTML5 Webcam API, client-side computer vision algorithms, and HTML5 LocalStorage, the application detects facial morphology, extracts high-dimensional biometric descriptors, calculates Euclidean distance metrics against an enrolled database, and triggers simulated electronic door unlock relays—all with zero reliance on cloud servers, Python backends, or third-party paid APIs.

System Architecture & Pipeline

End-to-End Client-Side Biometric Pipeline

1

Video Stream Acquisition (Browser Webcam API)

The client requests video capture using navigator.mediaDevices.getUserMedia(). Video frames are streamed locally without leaving the device.

2

Spatial Detection & Face Localization

A canvas-based chrominance (YCbCr) and facial aspect analyzer isolates the subject's face coordinates and draws a responsive bounding box HUD.

3

128-Dimensional Biometric Descriptor Extraction

The normalized facial crop is processed into a 128-element mathematical feature vector (HOG orientation gradients and deep feature representations) capturing facial landmarks.

4

Euclidean Distance Matching Engine

The real-time query vector is compared against all registered identities stored in LocalStorage using Euclidean distance: d(u,v) = √Σ(ui - vi)².

5

Access Decision, Software Relay Pulse & Audit Logging

If distance ≤ threshold (0.55), status is set to GRANTED, triggering an unlocked state for 5 seconds and recording a timestamped audit log.

Future Scope: Physical Hardware Integration

Conceptual Roadmap for Transforming Software Prototype into Hardware Deployment

Future Roadmap

While this academic prototype is strictly implemented as a software-only prototype running inside the web browser, the modular software architecture is designed to interface with physical IoT hardware in future expansion phases:

1. Embedded Edge Controllers

Deployment on single-board computers such as Raspberry Pi 4 (running Chromium in kiosk mode) or an ESP32-CAM microcontroller configured as a dedicated edge camera client.

2. Actuation & Locking Mechanism

Interfacing an electronic 12V Solenoid Door Strike or Electromagnetic Lock (Maglock) powered by an external 12V 2A DC supply, switched through an optocoupled 5V relay module with a 1N4007 flyback diode.

3. Motion Detection & Power Optimization

Integrating a PIR (Passive Infrared) Motion Sensor to trigger camera wakeup only when a human approaches the entryway, reducing continuous camera sensor draw and power consumption.

4. Hardware Bridge Communication

Triggering physical unlock pulses from the browser via the Web Serial API (direct USB connection to microcontroller) or local IoT publish/subscribe protocols such as MQTT over WebSockets.

Academic Clarity: In the current version, all physical lock signals are represented virtually by the application's software state machine, demonstrating complete end-to-end viability before physical fabrication.
